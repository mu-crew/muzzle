# muzzle 0.2.1: rules that match command words

Status: approved by the human (2026-10-30, Q1–Q3 "agreed, let's fix all
this"). Revised after a REFUTED refuter pass (R1–R7, orchestrator's calls). It amends the 0.2 spec (`2026-10-30-muzzle-0.2-paths.md`) and the
v1 spec's §Config and D22. This spec wins where they disagree.

## Problem

linuxpc's rules are regexes of about 300 characters. About 90% of each is
the same prefix, which says "the command word is in command position":
after `; & | (`, inside `-c '…'`, past `env`, `timeout`, `nice` and
`A=1`. Only the tail differs (`contrib/fast-gate`, `cargo (test|…)`). They
are hard to read, easy to get wrong, and already miss real shapes:
`mise exec -- …` matches only by accident, and `flock` and container entry
need hand-made alternations. muzzle already has a shell tokeniser
(`src/rules/shell.rs`, D16a) that finds command words properly; rules don't
use it.

## Decisions

**C1 `command` rules** (Q1). A rule sets exactly one of:

- `command = "<words>"` or `command = ["<words>", …]`: the normal form.
- `match = '<regex>'`: the escape hatch, unchanged from 0.2.

Setting both, or neither on a new rule, exits 2. In a `[path]` override
entry, which merges by name (P3), setting `command` replaces an inherited
`match` and the other way round: the matcher is one field.

**C2 Matching a `command` pattern.** A pattern is whitespace-separated
words: the first is the **program**, the rest are **subcommand words**.
For the command text:

1. Tokenise with `shell::commands`, which gives every simple command,
   including those after `;`, `&&` and `|`, in `$( )` and backticks, and
   (recursively) inside `bash -c '…'`, `sh -lc '…'` and so on.
2. For each simple command, strip assignments, keywords and wrappers
   (`strip_prefix`, extended by C3).
3. The **program** matches the first remaining word when the word equals
   it or ends with `/<program>`. So `contrib/fast-gate` matches
   `./contrib/fast-gate` and `/abs/x/contrib/fast-gate`, and `cargo`
   matches `/usr/bin/cargo`.
4. Each **subcommand word**, in order, must equal the next remaining word
   that doesn't start with `-` or `+`. Option words are skipped. A word
   after an option isn't treated as the option's argument; that's a
   documented heuristic, the same as git's. So `cargo +nightly test -p x`
   and `cargo --locked test` match `cargo test`, and `cargo +nightly fmt`
   doesn't. Extra words after the pattern are fine.
5. A rule matches when any simple command matches any of its patterns.
   Rule order and first-match-wins are unchanged (P4).

Quoted arguments, heredoc bodies and comments are never command words, so
`pgrep -f 'contrib/fast-gate'`, `cat scripts/check.sh` and
`echo "cargo test"` don't match, with no special care in the rule.

**C3 Wrappers and container entry** (Q2). There's one fixed table in code,
shared with container detection:

- **Added wrappers:**
  - `mise exec [opts] --` (and `mise x`);
  - `uv run [opts]`;
  - `npx [opts]` (`npx vitest` gives program `vitest`);
  - `flock [opts] <lockfile>`, where the lockfile is a positional word,
    and `-c '<cmd>'` is handled like `sh -c`;
  - `nohup` (already a keyword);
  - `time` (already present).
- **Container entry descends:**
  - `distrobox enter [opts] <box> -- <cmd…>`;
  - `distrobox-enter … -- <cmd…>`;
  - `toolbox run [-c <box>] <cmd…>`;
  - `podman|docker exec [opts] <ctr> <cmd…>`.

  The inner command is matched like any other, so a swayward gate typed as
  `distrobox enter swayward-dev -- bash -lc 'contrib/fast-gate'` matches
  `fast-gate`. Container detection (D16a) is unchanged: the job still
  counts as a container job.
- `runs_muzzle` (D22) keeps its own behaviour: it looks at the first simple
  command only.

**C4 What a match reports.** `match --json` keeps its 0.2 shape. The Claude
hook rule "allow only when the match starts at the command word" (D25)
becomes:

- For a `command` rule: allow only when the text is one simple command
  whose own words (not a nested `-c` script and not a container's inner
  command) match the pattern after the narrow `ALLOW_PREFIXES` strip.
- For a `match` rule: unchanged.

A nested or wrapped match is still claimed by `wrap`; the hook just leaves
it to the user to approve, as today.

**C5 Hash.** The config hash (P7) covers `command` as written, with the list
normalised to an array. A rule's matcher field is `command` or `match`, so
switching from one to the other changes the hash.

**C6 The linuxpc config and the museum check** (Q3).

- The live `~/.config/muzzle/config.toml` and `bench/linuxpc-config.toml`
  move to `command` rules.
- `oracle-sweep` stays a `match` rule. Its `exec 9>>$L; flock 9` and
  `flock -n … true` shapes aren't a command word.
- **The check:** a test script runs every museum bash command in the
  baseline (the deduplicated `swayward` and `mu` rows, 37,990, cached in
  `/tmp/pb`) through old and new configs with `muzzle match`, and diffs
  the rule per command.
  - Every difference is listed in `docs/eval/2026-10-30-command-rules.md`
    and classed as a **fix** (the old regex was wrong) or a **regression**.
  - Zero regressions is the bar. Each fix gets a one-line reason.
- The bench traces were labelled with the old config. They are not
  relabelled: the trace is the workload, and labels only pick the rule.

**C7 Docs.** The template, SKILL.md, `tune.md`, README, usage and the 0.2
spec's examples use `command`. `match` is documented once, as the escape
hatch.

**C8 Version.** 0.2.1, additive: every 0.2.0 config still loads.

## Revisions after the refuter (orchestrator's calls, 2026-10-30)

A refuter prototyped C2/C3 against the 37,837 distinct baseline commands
(REFUTED, `delegate_refute-021`). These revisions replace the matching parts
of C2, C3, C4 and C6.

**R1 Script programs.** A simple command whose program is a script, meaning
a word ending in `.sh`, or `bash|sh|zsh <file>` with no `-c` (the file is
the program), is matched three ways. A rule matches if any of them does:
1. the script path itself is the program, so `bash scripts/check.sh` and
   `scripts/check.sh` both match `command = "scripts/check.sh"`;
2. its arguments after any leading number words form a command: for
   `exec.sh npx vitest run`, the words `npx vitest run`;
3. each single argument word is tokenised as shell text: for
   `fx17-in.sh 'contrib/gate > x'` and `dbx.sh 2400 "contrib/gate | tail"`,
   the word `contrib/gate`.

This replaces the old regex's `\S+\.sh\s+(\d+\s+)?['"]?` branch for the same
shape.

**R2 Prefix words.** A pattern word may end in `*`, which matches any word
with that prefix: `npm run test*` matches `test`, `test:fast` and
`test:stress`. There's no other glob syntax.

**R3 Variable programs.** A program word that is a variable expansion
(`$D`, `${D}`) is stepped over like a wrapper, and the rest is matched. So
`D="distrobox enter b --"; $D bash -c 'contrib/gate'` matches through the
`-c` script.

**R4 Option arguments.** Wrappers and programs get explicit tables of
options that take an argument:
- **Descent wrappers:**
  - `podman|docker exec`: `-w --workdir -u --user -e --env --env-file
    --detach-keys`, then the container word;
  - `flock`: `-w --timeout -E --conflict-exit-code`; `-c <cmd>` is shell
    text; the first positional word is the lock;
  - `toolbox run|enter`: `-c --container -d --distro -r --release`;
  - `distrobox enter`: skip to `--`; `-n --name` takes an argument;
  - `mise exec|x`: skip to `--`;
  - `npx`: `-p --package`; `-c <cmd>` is shell text;
  - `uv run`: `--with --python -p --project --directory --extra --group
    --env-file --package`.
- **Programs**, for subcommand matching:
  - `cargo`: `-Z -C --config --color`;
  - `npm`: `--prefix -w --workspace`.

  Unlisted options don't take an argument, as in C2. C2's "the same as
  git's" claim is dropped.
- **Container detection (D16a) keeps its own `tool_enters` table
  unchanged.** Descent is a separate table, so detection doesn't narrow:
  `docker compose exec`, `docker -H x exec` and `toolbox enter` are still
  detected even where descent doesn't go.

**R5 Hook (C4) is exact.** `hook claude` allows only when:
- the text is one simple command;
- `command_word` finds its word, with today's rejections (`env -S`, a
  shell or wrapper as the word, and so on);
- that word equals the pattern's program, or is `./` plus it. Paths
  elsewhere don't count: `/tmp/evil/cargo` and `/x/contrib/fast-gate`
  aren't allowed;
- its own words match the subcommand words.

*Amended 2026-10-30 (review fix-rules-allow):* prefixes are held to the
same bar as the word. A prefix (`env`, `time`, `timeout`, `nice`) counts
only as a bare name or from `/usr/bin/` or `/bin/`: `/tmp/evil/env` and
`./time` aren't allowed. `env -C`/`--chdir` is rejected like `env -S`,
since it moves what a relative word resolves to. Options that name other
code to run (cargo `-C --config --manifest-path`, npm `-C --prefix`) block
the allow in any spelling (`-C/x`, `--config=…`) and on either side of the
subcommand, up to `--`.

Matches through C3 wrappers (`npx`, `mise exec`, `distrobox`), scripts (R1)
or variables (R3) are wrapped but never auto-allowed. That makes
`npx vitest run` lose auto-allow, which is listed in the CHANGELOG.

**R6 What counts as a regression (C6).** The museum check:
- runs each row with `--cwd` set to the worktree path decoded from the
  row's session folder (pi stores sessions per cwd), so `[path]` rules are
  exercised;
- puts rows that are exactly 300 characters long (truncated by the
  export) in their own bucket, reported but outside the bar. That's 47% of
  rows: the bar applies to complete commands only;
- treats a difference on a complete row as a **regression** if the text
  runs the rule's program in command position, directly or through
  C3/R1/R3, and the new rules miss it.

  These are **accepted misses**, not regressions:
  - work inside a heredoc-fed interpreter (`python3 - <<EOF …
    subprocess…`);
  - a script that the same text writes and then runs (P12: the human's
    policy is that hidden work isn't chased, and the old regex caught it
    only by accident).

  Everything else is a **fix**: prose inside quotes, `grep -E vitest`,
  `git log -- contrib/gate`, `ssh host '…'`.
- **Bar:** zero regressions. The eval note lists every regression,
  accepted miss and fix bucket, with counts and examples. The baseline
  count is whatever the script reports after deduplication; the 37,990 in
  C6 is replaced by the script's number.

**R7 Minor.**
- C5 normalises whitespace inside patterns before hashing.
- `runs_muzzle` (D22) doesn't descend.
- `flock`'s positional is the lock or a file descriptor. `flock 9` with no
  command after it matches nothing.
- `oracle-sweep` stays a `match` rule, listed first.

## Replay plan change

The tier-2 runner (`~/.cache/muzzle-bench/proof-replay.sh`) is stopped
until 0.2.1 is installed in the dogfood build and the live config is moved
over. It then restarts unchanged: it reads the live config at replay time.
Its `real-*.toml` command strings already use the shapes C3 matches.

## Scope

**In:** C1–C8, tests for every C2 and C3 case, and the museum diff.

**Out:**
- user-configurable wrappers;
- glob patterns in `command`;
- matching option values (`cargo test -p foo` as a pattern word);
- relabelling traces.

## Implementation checklist

1. `rules/shell.rs`: C3 wrappers and container descent. Add
   `pub fn command_heads(text) -> Vec<Vec<String>>` (stripped simple
   commands, recursing into `-c` scripts and container entries) and
   `pub fn head_matches(head: &[String], pattern: &[String]) -> bool`
   (C2 rules 3 and 4).
2. `rules/config`: the `command` field, validation (exactly one matcher),
   the merge rule (C1), the hash (C5). `Rule` gets
   `matcher: Matcher::{Command(Vec<Vec<String>>), Regex(Regex)}`.
3. `rules/resolve` and `Effective::matches`: dispatch on `Matcher`.
   `hook.rs`: C4.
4. Museum diff script and eval note (C6); live config and
   `bench/linuxpc-config.toml` rewritten.
5. Docs (C7), CHANGELOG, 0.2.1.
