# muzzle 0.3.3: different-PID deadlock & orphan-hold guards

Status: revised draft (2026-11-23, post-refutation wave `spec-refute`).
Amends D16, D17, D19 and adds `muzzle drop` plus additive fields to
`state.json`, `runs.jsonl`, `status --json` and `config.toml`. This spec
wins where it and the v1 spec disagree.

## Problem

D17 prevents a process tree from deadlocking itself through ancestry or
`MUZZLE_HOLD`, but it cannot see **different-PID deadlock cycles** where
two independent muzzle invocations share an external wait edge:

```
agent P ──waits on──▶ bash call B (muzzle waiter)
  ▲                         │
  │                    waits on slots
  │                         ▼
  └──only P can reap── holder A (backgrounded &/nohup, parallel call, or leaked D16 pgid)
```

In 232 recent multi-agent sessions on a 16-core macOS host (2026-11-21–22), 13
sessions had an agent queue behind its own muzzle claim:

1. **Explicit backgrounding (`&` / `nohup`)**: a worker backgrounded
   `(muzzle run --rule js-test …) &` to dodge a bash tool timeout, then
   issued a second heavy command whose muzzle was a sibling (not a
   descendant) and queued behind its own claim.
2. **Parallel tool calls**: an agent issued two `muzzle run --rule gate`
   calls in the same turn; the second sat queued behind the first until
   the bash tool timed out.
3. **Leaked idle servers pinning D16 holds for hours**: two dead holders
   (`reviewer-1` `pid 1750`, held `22,130 s`; `reviewer-2` `pid 49602`,
   held `8,005 s`) pinned 8 of 10 slots via surviving processes in their
   process groups (leaked private `tmux`/`rex` test servers, and a
   timed-out `(muzzle run … | tail -3)` where `muzzle` was not the group
   leader and was SIGKILLed without running `deadline.drain()`). Both
   reviewers queued behind their own dead claims for 63–78 minutes, and
   five other agents stacked up behind them until manual cleanup.

A fourth case—true cross-agent cycles where agent A holds slots while
waiting over IPC/DB on agent B, and B queues in muzzle behind A—has no
OS-level edge muzzle can inspect.

## Decisions

### G1 — Idle release and TTL on orphaned/kept holders (amends D16)

D16 keeps a claim alive after the top command or muzzle exits so a
leaked *building* job still accounts for its slots. It is not meant to
hold slots indefinitely for an idle leaked server (`tmux`, `rex`, test
daemon).

Define a holder as **orphaned** when `h.kept || !live.alive(h.pid, h.start)`
(a keeper holds the entry, or muzzle itself died and only its group/scope
remains). A healthy foreground holder (`!h.kept && live.alive(…)`) is
never affected by G1.

1. **Unconditional orphan clock (`orphan_since_ms`):**
   - As soon as a holder is observed orphaned—regardless of whether CPU
     figures are readable or whether a `pgid` exists—set
     `orphan_since_ms` once:
     - For a `kept` holder: `keeper.rs` sets `orphan_since_ms = Some(now)`
       at handoff (`keep()`), and also runs the G1 idle/TTL check in its
       own poll loop.
     - For a `dead-muzzle` holder (`!h.kept && !live.alive(…)`): `admit`
       sets `orphan_since_ms = Some(h.seen_ms.unwrap_or(now).min(now))`.
       Because `seen_ms` tracks the last heartbeat or admit sighting, a
       dead holder that sat unpolled for 10+ minutes already has its
       elapsed orphan age accounted for on the first poll.

2. **Per-member idle release (`orphan_idle_s`, default `120` s; `0` disables):**
   - `Liveness` gains `group_cpu(&self, pgid: u32) -> Option<Vec<ProcCpu>>`,
     where `ProcCpu { pid: u32, start: u64, cpu_ns: u64 }` reads user +
     system CPU nanoseconds per live member of `pgid` (`/proc/<pid>/stat`
     fields 14–15 converted via `sysconf(_SC_CLK_TCK)` on Linux;
     `PROC_PIDTASKINFO` `pti_total_user + pti_total_system` converted via
     `mach_timebase_info` on macOS).
   - If *any* live member of `pgid` returns `EPERM` (e.g. a setuid child),
     `group_cpu` returns `None` rather than silently omitting it.
   - `Holder` gains optional fields (add-only in `state.json`):
     - `orphan_since_ms: Option<u64>`
     - `orphan_active_ms: Option<u64>` — last time the group showed
       activity.
     - `orphan_sample_ms: Option<u64>` — timestamp of the last CPU
       snapshot (so `dt` is always well-defined).
     - `orphan_procs: Option<Vec<ProcCpu>>` — previous per-member CPU
       snapshot (populated only while orphaned; capped at 64 members).
   - On each `admit` pass (and keeper poll) for an orphaned holder with
     `pgid = Some(g)` when `group_cpu(g)` returns `Some(cur)`:
     - On first sample (or if `cur.len() > 64`): set `orphan_active_ms =
       now`, `orphan_sample_ms = now`, `orphan_procs = Some(cur)` (capped).
     - On subsequent samples when `dt_ms = now.saturating_sub(prev_ms) > 0`:
       the group counts as **active** if either:
       1. any `(pid, start)` in `cur` was not in `prev` (a new process
          was spawned), OR
       2. the sum of positive per-member `cpu_ns.saturating_sub(prev_ns)`
          over `(pid, start)` present in both `prev` and `cur` is at
          least `1%` of one core over `dt_ms` (`dcpu * 100 >= dt_ms *
          1_000_000`).
       Using per-member deltas ensures a high-CPU member exiting between
       polls never makes a busy survivor look idle.
     - Always update `orphan_sample_ms = Some(now)` and `orphan_procs =
       Some(cur)` when `dt_ms > 0`; advance `orphan_active_ms = Some(now)`
       only when active.
     - If `orphan_idle_s > 0` and `now.saturating_sub(orphan_active_ms)
       >= orphan_idle_s * 1000`, prune the holder and append a run record
       with `killed: "orphan-idle"`.
   - If `group_cpu` returns `None` (EPERM, or a container scope with no
     host `pgid` members), idle release does not fire; only the TTL
     backstop applies.
   - Idle release frees the **slot claim only**; muzzle does not signal
     the surviving processes. The 120 s default gives a briefly
     network-blocked orphaned `npm ci` / `cargo fetch` two minutes of
     grace while still clearing leaked idle servers ~100× faster than a
     6-hour wedge.

3. **Hard TTL backstop (`orphan_ttl`, default `600` s; `0` disables):**
   - When `orphan_ttl > 0` and `now.saturating_sub(orphan_since_ms) >=
     orphan_ttl * 1000`, prune the orphaned holder even if it is still
     burning CPU or unreadable, and append `killed: "orphan-ttl"`.

4. **Keeper exit on prune (`src/run/keeper.rs`):**
   - In `keeper.rs`, both the heartbeat and the poll loop check whether
     `s.holder_mut(self.ticket)` still exists. If the ticket was pruned
     (by G1) or dropped (by G4), the keeper exits cleanly at once without
     rewriting `state.json`, without signalling the group, and without
     writing a duplicate `runs.jsonl` line.

`admit::admit` remains pure (no I/O): CPU readings come through
`Liveness`, and thresholds (`orphan_idle_s`, `orphan_ttl`) come through
an `AdmitConfig` struct.

### G2 — Same-caller overlap guard (different-PID self-deadlock)

1. **Caller identity:**
   - `src/run/mod.rs` reads `MU_AGENT_NAME` into `Claim.agent` (not
     `MU_AGENT`), and `TMUX_PANE` into `Claim.pane`. Because `mu`
     uniqueness is `(workstream_id, name)`, `MU_AGENT_NAME` alone can
     collide across workstreams or remote origins.
   - Define a holder and a new `muzzle run` as the **same caller** when:
     - both have `pane: Some(p)` with the same `p`, OR
     - neither has `pane`, and both have `agent: Some(a)` and the same
       `cwd` (or `repo: Some(r)`).
   - Anonymous callers with neither `pane` nor `agent` are never subject
     to G2.

2. **Immediate diagnostic (always, at t=0, after D17 `is_nested` check):**
   - Under the initial state lock (before waiting), if `state.holders`
     contains any live-in-state (`holds()`) holder belonging to the same
     caller, print one line to stderr immediately naming its ticket,
     slots, state (`live`, `kept`, or `dead-muzzle`), elapsed time, and—for
     orphaned holders—up to 3 surviving members `comm(pid)`:
     ```
     muzzle: warning: same pane (%12 / reviewer-2) already holds 4 slots (ticket 42, dead-muzzle 914s, pgid 49602: tmux(51234))
     ```

3. **Fail-fast ONLY when blocked by own orphaned claim:**
   - Harmless parallel bash tool calls (two live calls from the same
     agent) are **not** refused—they warn at t=0 and queue normally.
   - Refuse admission with exit **76** (`exit::SELF_OVERLAP`,
     `EX_PROTOCOL`) **only** when all of the following hold on the
     initial `admit` pass:
     1. the new request was not admitted immediately,
     2. the same caller holds at least one **orphaned** (`kept` or
        `dead-muzzle`) claim (`own_orphan_held > 0`), and
     3. those orphaned slots are actually part of what blocks admission:
        `need > free && need <= free + own_orphan_held`.
   - Print an actionable message pointing directly to `muzzle drop`
     (which requires no `--force` for orphaned holders):
     ```
     muzzle: refusing to queue behind own orphaned claim (ticket 42, 4 slots, dead-muzzle 914s); run `muzzle drop 42` (or `muzzle drop --kill 42`) or pass --allow-concurrent
     ```
   - On exit 76, write `--report` (if requested, so pi's extension renders
     a clean `muzzle:` line instead of "No report") and append a
     `runs.jsonl` record with `killed: "self-overlap"`, `waited_s: 0.0`,
     `ran_s: 0.0` so G2's rate is measurable in `report`.
   - Opt-outs: `--allow-concurrent` on `muzzle run`, or
     `allow_concurrent = true` in `config.toml` (warning still prints).

### G3 — Visibility in `status` and `queued` lines (add-only)

1. **`status --json`** (`HolderView` in `src/status.rs`): add fields
   only, never rename or remove:
   - `ticket: u64`
   - `state: "live" | "kept" | "dead-muzzle"`
   - `orphan_s: Option<u64>` (seconds since `orphan_since_ms`, `null`
     when `state == "live"`)
   - `procs: Vec<GroupProc>` (`{ pid: u32, comm: String }`, capped at 8
     entries; populated only when `state != "live"`, `[]` when `live`).
2. **Human `muzzle status`**: show `#<ticket>` and, for `kept` or
   `dead-muzzle` holders, append the state and surviving members:
   ```
   #42  4 slots  normal  reviewer-2  js-test  914s  [dead-muzzle 910s, pgid 49602: tmux(51234)]  /path/...
   ```
3. **`muzzle: queued` lines**: tag orphaned holders so waiters see at a
   glance why slots aren't freeing:
   ```
   muzzle: queued 2/5, 8/10 slots held (reviewer-1 js-test 4 [dead], reviewer-2 js-test 4 [dead])
   ```

### G4 — Escape hatch: `muzzle drop`

Add a `muzzle drop` subcommand so agents and humans can clear wedged
claims without editing `state.json` or bypassing muzzle:

```sh
muzzle drop <TICKET>...           # drop specific holder(s)
muzzle drop --dead                # drop all dead-muzzle and kept holders
muzzle drop --agent <NAME>        # drop dead/kept holders for NAME
muzzle drop --kill <TICKET>...    # also SIGTERM -> 5s -> SIGKILL surviving members
muzzle drop --force <TICKET>...   # allow dropping a healthy live holder
```

- Without `--force`, `muzzle drop` refuses to drop a `live` holder
  (exit 2).
- **Safe `--kill` (no PGID-reuse race, no lock held during grace):**
  - Read the holder's `pgid` and snapshot its current `(pid, start)`
    members owned by the current uid, excluding `muzzle drop`'s own
    process group.
  - Release the state lock before signalling. Send `SIGTERM` to each
    verified `(pid, start)` (checking `proc::alive(pid, start)`), wait up
    to 5 s polling every 100 ms until all exit, then send `SIGKILL` only
    to those still matching `(pid, start)`.
  - Remove the holder from `state.json` *after* `--kill` finishes (so
    new jobs don't start while the old one is still shutting down).
  - If `pgid == None` (admitted, not yet spawned): refuse `--kill`
    (nothing to signal yet). In `src/run/job.rs` `spawn_recorded`, check
    that `s.holder_mut(self.ticket)` still exists *before* `cmd.spawn()`
    so a `--force` drop before spawn aborts cleanly instead of launching
    an unclaimed job.
  - For D16a container scopes (`h.scope.is_some()`): if systemd user
    manager is reachable, call `stop_unit`; otherwise drop the slot claim
    and warn on stderr that the container workload could not be stopped.
- **No double-logging on foreground `--force` drop (`src/run/report.rs`):**
  - `release()` appends a run record only when `s.remove(self.ticket)`
    returns `true` (if the ticket was already dropped/pruned, its
    terminal record was already written).
- Each dropped holder is logged to `runs.jsonl` with `killed: "dropped"`.
- Prints a one-line summary of dropped tickets (exit 0 if `--dead` finds
  nothing to drop).

### G5 — Default queue timeout for cross-agent cycles

True multi-agent deadlock cycles (A holds slots waiting over IPC/DB on
B; B queues in muzzle behind A) cannot be detected by muzzle alone. A
bounded queue wait ensures they break cleanly instead of wedging
indefinitely:

- Add optional `queue_timeout` (seconds, `f64`) to `config.toml` and
  `MUZZLE_QUEUE_TIMEOUT` to the environment.
- Precedence: `--no-timeout` / `--timeout` flag > `MUZZLE_QUEUE_TIMEOUT`
  > `config.toml` `queue_timeout` > none (wait indefinitely).
- **Preserve `--timeout 0`**: `--timeout 0` keeps its existing meaning
  ("try once, then exit 75"). Use `--no-timeout` (or
  `MUZZLE_QUEUE_TIMEOUT=none`) to disable a configured default and wait
  indefinitely.
- On expiry, leaves the queue, exits `75` (`EX_TEMPFAIL`), and prints
  the current holders (with G3's `[dead]`/`[kept]` tags).
- Keep `queue_timeout` unset by default for human/interactive use;
  recommend `MUZZLE_QUEUE_TIMEOUT=900` (15 min) in managed-agent launch
  environments (which also avoids breaking older muzzle binaries on
  hosts whose `config.toml` uses `deny_unknown_fields`).

### G6 — Harness and skill ergonomics

1. **muzzle skill (`npm/muzzle/skills/muzzle/SKILL.md`)**:
   - Update the backgrounding note: warn that launching a second heavy
     command while a backgrounded `muzzle run` still holds slots can
     self-block or trip exit 76; prefer foreground `muzzle run
     --run-timeout S` over `&`/`nohup`.
   - Reinforce the non-leader rule: never wrap `muzzle run` in a
     subshell or pipe `(muzzle run … | tail)`; put pipes inside
     `bash -c '…'` so `muzzle` leads the group and tears down children
     cleanly on timeout.
   - Document `[dead]`/`[kept]` in `muzzle status`, exit `76`, and
     `muzzle drop` (including `--kill`) as the recovery path instead of
     bypassing muzzle.
2. **Harness timeout signal order (out-of-repo note for pi / mu)**:
   - On bash tool timeout, send `SIGTERM` to the shell's process group
     with a short grace (2–5 s) before `SIGKILL`. That gives even a
     non-leader `muzzle` time to run `deadline.drain()` and kill its
     child's separate `pgid`, preventing orphaned groups from being
     created in the first place.

## Schema & compatibility

| surface | additions | compatibility notes |
| --- | --- | --- |
| `state.json` (`Holder`) | `orphan_since_ms`, `orphan_active_ms`, `orphan_sample_ms`, `orphan_procs` (all `Option<…>`, `#[serde(default, skip_serializing_if = "Option::is_none")]`) | Additive. If an older muzzle rewrites `state.json`, it drops these fields; newer muzzle re-initialises them on the next pass (note: if an older muzzle is actively heartbeating on the same host, upgrade muzzle on the host before relying on G1). |
| `runs.jsonl` (`Killed`) | `"orphan-idle"`, `"orphan-ttl"`, `"dropped"`, `"self-overlap"` | Additive enum variants; `src/report/` checks `killed.is_none()` for clean runs and `killed == Some(Killed::Oom)` for OOM, so no existing aggregation breaks. |
| `status --json` (`HolderView`) | `ticket`, `state`, `orphan_s`, `procs` | Strictly additive; existing fields untouched. |
| `config.toml` | `orphan_idle_s`, `orphan_ttl`, `queue_timeout`, `allow_concurrent` (excluded from `config::hash` so tuning history is preserved) | `Layer` uses `deny_unknown_fields`: upgrade muzzle on a host before adding these keys to `config.toml` (same as `overcommit` in 0.2.5). Env var `MUZZLE_QUEUE_TIMEOUT` is ignored by older binaries. |
| Exit codes (`src/exit.rs`) | `SELF_OVERLAP = 76` | Distinct from `75` (`QUEUE_TIMEOUT`), `124` (`RUN_TIMEOUT`), `125` (`INTERNAL`), `2` (`USAGE`). |

## Architecture & affected units

- `src/proc/{mod,linux,macos}.rs`: `group_cpu(pgid) -> Option<Vec<ProcCpu>>`
  and `group_procs(pgid) -> Vec<(Pid, String)>` (`comm` from
  `/proc/<pid>/stat` on Linux, `PROC_PIDT_SHORTBSDINFO.pbsi_comm` on
  macOS; CPU time from `/proc/<pid>/stat` fields 14–15 with `CLK_TCK` on
  Linux, `PROC_PIDTASKINFO` + `mach_timebase_info` on macOS).
- `src/state.rs`: `ProcCpu`, optional orphan-tracking fields on `Holder`,
  new `Killed` variants.
- `src/admit.rs`: pure orphan idle-release and TTL logic in `admit()`,
  driven by `Liveness::group_cpu` and `AdmitConfig`.
- `src/exit.rs`: `SELF_OVERLAP = 76`.
- `src/cli.rs` & `src/main.rs`: `--allow-concurrent` and `--no-timeout`
  on `RunArgs`; new `Drop(DropArgs)` subcommand.
- `src/run/{mod,queue,job,keeper,report}.rs`: G1 keeper orphan init +
  missing-ticket exit; G2 same-caller diagnostic & orphaned-blocker exit
  76 + report/runlog write; G3 `[dead]`/`[kept]` tags in `progress_line`;
  G4 pre-spawn holder check + no double-log in `release()`; G5
  `queue_timeout` resolution.
- `src/status.rs`: G3 additive `HolderView` fields and human rendering.
- `src/drop.rs` (new unit): G4 `muzzle drop` with `(pid, start)`-verified
  `--kill`.
- `src/rules/config/`: G1/G2/G5 optional top-level config keys (excluded
  from `config::hash`).
- `npm/muzzle/skills/muzzle/SKILL.md`: G6 guidance.

## Verification plan

1. **Pure unit tests (`src/admit.rs`)**:
   - Live muzzle with 0 CPU is never pruned by idle release or TTL.
   - Orphaned (`kept` or dead-muzzle) holder with 0 CPU delta across
     `orphan_idle_s` is pruned with `killed: "orphan-idle"`.
   - Member exit between polls (`41s -> 31s` total, survivor burning
     100% CPU) is treated as **active**, not idle.
   - Same-millisecond polls (`dt_ms == 0`) do not advance
     `orphan_active_ms`.
   - Orphaned holder burning ≥1% CPU stays held past `orphan_idle_s`,
     then is pruned at `orphan_ttl` with `killed: "orphan-ttl"`.
   - Orphaned holder with `group_cpu == None` still initializes
     `orphan_since_ms` (using `seen_ms` for dead-muzzle) and is pruned
     at `orphan_ttl`.
2. **Same-caller overlap & `queue_timeout` (`src/run/`)**:
   - Same `pane` blocked by own orphaned claim exits 76 at t=0, writes
     `--report`, and appends `killed: "self-overlap"`.
   - Same `pane` with two live claims warns at t=0 and queues normally
     (no exit 76).
   - Two different panes sharing `MU_AGENT_NAME` do not trigger G2.
   - `--allow-concurrent` and `allow_concurrent = true` proceed to queue.
   - Nested claim (D17) runs immediately and never trips G2.
   - `queue_timeout` precedence (`--no-timeout` / `--timeout` >
     `MUZZLE_QUEUE_TIMEOUT` > `config.toml`), and `--timeout 0` still
     tries once and exits 75.
3. **Platform & CLI integration (`tests/`)**:
   - Background `sleep` hands off to keeper, `status --json` reports
     `state: "kept"` and `procs` contains `sleep`, idle release frees
     slots after `orphan_idle_s` without killing `sleep`, and the keeper
     exits cleanly without double-logging.
   - `muzzle drop --dead` clears a wedged claim and logs
     `killed: "dropped"`; `muzzle drop` refuses a live holder without
     `--force`; `--kill` terminates verified `(pid, start)` members
     without holding the state lock during grace; foreground `--force`
     drop does not double-log.
   - macOS CI run green for `PROC_PIDTASKINFO` + `mach_timebase_info`
     and `pbsi_comm`.

## Open

- **Idle threshold tuning**: 1% of one core over 120 s is conservative
  for an idle `tmux`/`rex` server (<0.05%) while tolerating a briefly
  network-blocked orphaned `npm ci` / `cargo fetch`; measure on real
  workloads before locking the default.
- **Container scopes (D16a)**: reading CPU delta from a systemd scope's
  `cpu.stat` (`usage_usec`) would extend idle release to container runs
  too; left for follow-up since the TTL backstop already bounds them.
